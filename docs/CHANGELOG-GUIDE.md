# 更新日志书写规范

`CHANGELOG.md` 是写给用户看的。每个版本的小节会原样出现在三个地方：

- GitHub Release 说明（发版 CI 自动截取，见 [RELEASE.md](RELEASE.md)）
- 官网「更新日志」页（按版本排成时间线）
- 应用内的更新提示窗口

读者是普通用户，不是开发者。技术细节写进提交记录和 `docs/`，不进 CHANGELOG。

## 结构

```markdown
## 0.2.0

<!-- min-version: 0.2.0 -->

新增 Windows 应用内一键更新，并修复了几处贴边问题。

### 新增

- 启动时自动检查更新，Windows 版可在提示窗口里一键更新。

### 改进

- 对话气泡的字号随人物大小调整，小尺寸下也能看清。

### 修复

- 贴边后偶尔无法拖动。
```

逐项说明：

1. **版本标题**：`## ` 加版本号，版本号与 tag 一致，不带 `v`，后面不加说明文字。发版 CI 按这一行找小节，找不到或小节为空会让发版失败。
2. **最低可用版本**（可选）：一行 HTML 注释 `<!-- min-version: x.y.z -->`，表示低于该版本的用户必须更新。有这一行时，应用内的提示窗口不能关闭，官网会给这个版本标上「重要更新」。注释在页面上不显示。只在旧版本无法正常使用、存在数据风险，或旧版本已经连不上服务时使用。
3. **概述**：分组前写一段话，一到两句，说明这个版本最主要的变化。用户往往只读这一句。
4. **分组**：只用下面三个标题，没有内容的分组不写，顺序固定：
   - `### 新增`：以前没有的功能。
   - `### 改进`：已有功能变得更好用、更快或更稳定。
   - `### 修复`：以前出错、现在正常的地方。
5. **条目**：每条以 `- ` 开头，一条一句，以句号结尾。

## 写法

**写用户能感受到的变化**，说清楚在哪里、有什么不同。

| 不要这样写 | 改成 |
| --- | --- |
| 修复 hit mask 在 DPI 变化后失效 | 修复切换屏幕缩放后，点不到桌宠的问题。 |
| 重构 GazeController，消除视线跳变 | 视线跟随鼠标更平滑，不再突然跳动。 |
| 升级 Live2D Cubism SDK 到 5-r.6 | 不写（用户感受不到）；如果带来可见的改善，写那个改善。 |
| feat: 新增 update 窗口 | 启动时自动检查更新，有新版本时弹出提示。 |
| 优化性能 | 待机时占用的电脑资源更少。 |
| 修复若干已知问题 | 写出具体是哪些问题；确实很零碎时写「修复了一些显示和操作上的小问题。」 |

**不要出现**：

- 文件路径、函数名、接口名、配置项、命令（如 `redesign/ui`、`window.petAI`、`tauri.conf.json`）。
- 内部术语和英文缩写（如 SDK、API、MSK、PR、WebView、掩码、壳）。可以用 Windows、Android、Live2D 这类产品名称。
- 提交前缀（`feat:` / `fix:`）、PR 编号、作者名、「What's Changed」这类自动生成的内容。
- 反引号、链接、图片、表格、多级列表。官网和应用内只支持标题、段落、`-` 列表和加粗，其余格式会显示成原文。加粗也尽量不用。
- 表情符号和装饰符号。

**用词**：

- 平台写「Windows 版」「Android 版」；条目只涉及一个平台时，在句首注明，例如「Windows：」「Android：」。
- 人物称 Aliya，不写「模型」「角色」。
- 称呼用户时用「你」，不用「您」，也不写「用户可以……」。
- 不夸张：不写「全新」「大幅」「极致」；能写数字就写数字，例如「启动时间从 3 秒缩短到 1 秒」。

## 流程

1. 改动用户可见的行为时，在同一个 PR 里把条目写进 CHANGELOG 顶部的待发版本小节。如果还没有这个小节，先建一个，标题写下一个版本号。
2. 准备发布（`release/<版本号>` 分支）时，通读整个小节：合并重复的条目，删掉用户感受不到的条目，补上概述，确认是否需要 `min-version`。
3. tag 推送后，发版 CI 会截取这一小节作为 Release 说明。发布服务每 10 分钟同步一次，官网和应用内会显示同样的内容。
4. 发布后发现说明写错了，直接在 GitHub 上编辑 Release 说明，官网和应用内会在下次同步时更新；同时改 CHANGELOG，保持两边一致。

## 发布前自查

- [ ] 标题是 `## x.y.z`，与 tag 一致。
- [ ] 有一句概述。
- [ ] 分组只用了 新增 / 改进 / 修复。
- [ ] 每条一句话，句号结尾，没有路径、接口名和英文缩写。
- [ ] 需要强制更新时写了 `min-version`，不需要时没写。
