# 普通互动规则

本地互动不调用 AI。输入识别、反应组播放、台词展示与自动行为分别负责自己的部分；
`InteractionCoordinator` 统一判断自动行为和台词能否开始。

## 操作约定

| 操作 | 反馈 |
| --- | --- |
| 左键轻点 | 按区域选择反应与台词；已有台词完整读完，不重复覆盖 |
| 左键移动超过拖动阈值 | 搬动桌宠；拖动期间保持「被拎起」姿态（睁大眼、微抬头、头随水平速度反向摆）；松开只处理拖动，不附带点击 |
| 右键按住头部往返移动 | 识别为抚摸后闭眼、跟随手势；右键轻按不计抚摸 |
| 触屏轻点头部 | 普通点击；往返滑动为抚摸，大幅未识别移动不算轻点 |
| 触屏（Android） | 16 CSS px 内抬手算轻点；悬浮宠按下移动即拖动，见 `ANDROID.md` |
| 连续点击 | 3 秒内 3 次 `repeat`，4 秒内 5 次 `annoyed`，6 秒内 8 次进入 3 秒冷却（冷却中只轻点头） |
| 快速拖动后松开 | 一次 `drag.fast` 反应；系统取消不触发 |
| 慢速拖动后松开 | 落地轻顿后回中，35% 概率带 `drag.slow` 台词 |
| Esc | 取消互动、关闭气泡；正在拖动时保存位置并收尾 |
| 失焦、pointercancel、异常丢失捕获 | 释放手势和参数覆盖，不产生结束台词 |

## 反应组

互动与 MSK 无关。每次互动按**触发键**从 `assets/interaction/reactions.json` 抽一个**反应组**并同时播放：

- 反应组 = `lines`（气泡台词，必填）+ `expression` 和/或 `action`（至少一个）。组内多条台词共用同一套表演。
- `expression` 是临时表情：随台词持续（按气泡节奏估算），无台词时 3 秒，之后回到当前状态的默认表情；聊天表演保持表情期间不覆盖。
- `action` 可以是 Live2D 动作或程序微动（名字都来自 `src/catalog.ts`，见 `PERFORMANCE.md`）。互动触发的 Live2D 动作 3 秒内不被下一次互动重启。组里没有程序微动时，点击补一个缺省微动（点头/单眼眨/睁大眼/落地），保证每次都有即时身体反馈。
- 同一触发键不连续抽到同一组；台词位被占（气泡在播、聊天占位、协调器拒绝）时只表演不说话，不积压。
- 加载时校验：没有台词、表情动作都缺、引用未知名字或不存在的组，一律丢弃并在控制台警告；`tests/catalog-reactions.test.mjs` 要求正式数据零问题。
- 台词带 `tags: ["ears"]` 的在隐藏猫耳时停用。

| 触发键 | 来源 |
| --- | --- |
| `click.<区域>` | 左键轻点命中区域；没有专属组的区域落到 `click.body` |
| `click.repeat` / `click.annoyed` | 连点递进；区域可用 `click.<区域>.annoyed` 覆盖（现有 head、face） |
| `drag.fast` / `drag.slow` | 拖动松手 |
| `petting.start/soft/active/fast/long/repeat/end` | 抚摸各阶段（触发时机见下） |
| `random`、`time.<时段>` | 随机台词：按两边可用台词数分配概率 |
| `greet` | 网页嵌入版首次问候 |

## 命中区域

`assets/interaction/aliya_hit_areas.json` 共 26 个椭圆（参考余量 1.22）：头、头顶、刘海、左右猫耳、
左右侧发、马尾（下段）、马尾上段、脸、眼睛、左右脸颊、嘴、下巴、左右肩、领带、胸口、手、平板、腰、
裙摆、腿、身体兜底；`head_pet_zone` 只用于右键抚摸判定（优先级 -1，不参与点击命中）。
坐标按正式 moc 各部件顶点包围盒标定；隐藏猫耳时耳朵区停用，点击落到头部。

## 生命周期与互斥

抚摸仅保留 `inactive → pressed → petting → finishing → inactive`。
进入抚摸时取消旧的程序化点击反应；收尾完成后停止写互动参数。
未识别成有效手势的按压不计入抚摸次数。按压期间释放无关鼠标按钮不结束抚摸。

拖动检测在实际超过移动阈值时才开始，使用屏幕坐标增量计算速度，避免窗口移动
抵消画布内坐标。普通点击、取消、重载均清理拖动检测状态。

「屏幕贴边」采用 [interact.js 的 endOnly / smooth end 交互](https://interactjs.io/docs/inertia/)：
拖动期间完全跟手，不锁边、不增加脱离阻力、不限制跨屏；开启时松手进入
48 CSS px 感应带或越界才归位。Web Animations API 使用统一 `--al-ease` 缓动，
约 220ms 平滑靠边（Android 悬浮窗由原生 `ValueAnimator` 同一曲线逐帧 updateViewLayout，
不受 JS 帧率/省电 15fps 影响，归位途中抓起即停在当前位置接着拖），少动态效果偏好下直接归位；再次抓取、位置重置或设置变化
立即取消旧动画。Windows 复用 Tauri 原生显示器选择（最大相交屏，完全出屏取
最近屏），按其工作区避开任务栏。贴边以舞台矩形（当前比例的自然窗口，含渲染余量的透明边）对齐工作区，不要改按可见轮廓对齐：感应带会缩到仅 48 CSS px，落点也会让舞台越出屏幕。松手后的边缘高亮（`snap-confirm`）画在 `#stage` 上：外窗是固定容量，缩小后外窗边在屏外，画在 body 上看不见。坐标存储和窗口操作统一用物理像素，感应
范围按目标屏 DPI 换算。关闭时屏外位置原样保留，找不回用设置页「位置重置」。pet 缩放时保持脚底
中心的屏幕位置不变；缩放尺寸仍限制在当前显示器可操作范围内。缩放过程：Windows 外窗逐帧
按同一比例指数逼近目标（`_runScaleAnimation`，时间常数 55ms，滑杆连续拖动时目标实时更新），
每帧经 `set_pet_bounds` 位置+尺寸一次原生提交、脚底固定，角色始终按窗口自然适配。WebView2
resize 后会把上一帧拉伸到新窗口显示一两帧，外窗与角色严格同比时这一帧恰好正确，因此不闪；
画内补间配合分步改窗会让拉伸帧与真实比例不一致（实测抽搐、先变大再缩小），不再使用。
启动恢复、少动态效果偏好时一步落定；Android 悬浮窗补间期间外窗按起止较大比例给足、缩小播完再收回，气泡与聊天入口同步跟随。
chat 是 pet 的从属窗口：按模型可见矩形（静态包围盒×渲染矩阵，底边=脚底）水平居中、
覆盖角色下半部，宽度跟随模型；窗口窄于 380 CSS px 时整页 `set_zoom` 等比缩小（高度与脚底偏移
同比），小模型旁的输入框不会比角色还大；详见 `CHAT.md`。pet 脚下的聊天入口按钮钉脚底
（逐帧校正 bottom），并随缩放档位等比缩放（--launcher-k，0.7–1.6）。

角色交互只认本体：按下时在触点周围（鼠标 6 / 触摸 10 CSS px）采样渲染缓冲 alpha，轮廓外的透明区
（头顶、发梢间隙）不触发点击/抚摸/拖动，跟随任意缩放、镜像与动作姿态；命中椭圆只负责区分部位语义。
Windows 原生穿透掩码 96 列（≈4 CSS px 一格）。

正在互动、说话、暂停或操作结束后的 2.5 秒内，不开始自动动作和闲聊。
自动动作也不打断尚未结束的动作。被阻止的随机行为不排队，下一次正常计时再判断。
已有动作可以自然收尾；此规则不是对所有 Live2D 参数施加强制冻结。

## 台词

抚摸阶段的触发时机：start 40%（当日已抚摸 ≥2 次时按概率改 repeat）、fast（>250px/s 持续 0.8s）、
long（10s）、soft/active（2s 起最多 2 条、间隔 4s、60%）、end（主动松手且 >1s 时 30%），
抽取时避开最近 4 条已播台词。闲聊只抽 `random` 与当前时段，排除点击、抚摸和其他时段。

身体反馈仍即时发生；气泡忙时跳过新台词，不积压过时回应。
AI 聊天经同一协调入口接入（说话状态包含对话生成与表演），
聊天自身的规则见 `CHAT.md`。

## 验证

在 `redesign/ui` 执行 `npm test` 与 `npm run build`。
回归测试覆盖采样频率、有效手势、取消、恢复、连点冷却、触屏轻点、
实际指针回调接线、气泡异步取消及自动行为计时器。

本轮自动测试不替代 Windows 原生窗口或 Android 真机的视觉手感验收。
尤其需现场体验不同 DPI/模型缩放的命中区域及触屏壳的原生拖动。
